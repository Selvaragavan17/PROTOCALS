The AHB master sequence focuses on verifying 32-bit word-aligned transfers by constraining the lower address bits to maintain proper alignment. Address values are generated using constrained randomization so that transactions cover a wide range of the defined address space.

To validate correct routing through the bridge, a weighted distribution mechanism is used. Most of the transactions (around 90%) are directed toward the DUT address region, while a smaller portion (around 10%) targets the active slave region. This helps confirm that address decoding and routing logic behave as expected.

The sequence supports burst transactions and exercises different burst types to verify correct handling of multi-beat transfers. Back-to-back transfers are also generated to check continuous traffic behavior on the AHB bus. In addition, BUSY transfers are inserted between valid transfers to ensure that the design correctly handles intermediate busy cycles as defined by the AHB protocol.

Successive transactions are exercised to validate proper sequential access behavior. The sequence waits for reset de-assertion and ensures clock stability before starting any activity, which helps verify correct reset synchronization.

Transactions are distributed across different slave address ranges to check address decoding functionality. Factory-based transaction creation is used within the UVM environment to keep the sequence flexible and scalable.

All randomized transactions are checked after generation to ensure that constraints are satisfied. This helps catch any unintended constraint failures and ensures that only valid stimulus is applied during simulation.

The APB slave sequence is designed to generate both OKAY and ERROR responses in order to verify normal operation as well as error conditions on the APB interface. The response type is controlled using weighted randomization so that both scenarios occur during simulation, while still maintaining a realistic distribution.

The sequence also supports programmable wait-state insertion. A randomized wait count is used to introduce variable delays, which helps verify bridge behavior during extended APB transfers. During these cases, the correctness of the PREADY signal is monitored to ensure proper behavior in both wait and completion phases.

PTIMEOUT functionality is verified by monitoring the number of inserted wait states. If the wait count exceeds the configured timeout limit, the transfer is aborted as expected. In addition, PSLVERR generation is supported to validate proper slave error propagation from the APB side to the AHB interface of the bridge.

A configuration option is provided to suppress slave errors when required. This allows selective validation scenarios depending on the test configuration.

The sequence behavior is aligned with both APB Revision 2 and Revision 3 specifications to ensure compatibility across different protocol versions.

Basic assertion checks are included to confirm correct response generation and proper randomization behavior. The sequence works in coordination with the AHB-to-APB transaction model to ensure accurate modeling of protocol-level interaction between both interfaces.
